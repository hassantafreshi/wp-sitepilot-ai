# رخداد ابزار QA محلی Activity Log

تاریخ ثبت: 2026-09-06

## اثر واقعی

در اجرای قبلی `local_activity_log_browser_fixture.php`، buffer قبلی گزینهٔ `aisaautopilot_logs` در WordPress محلی پاک شد. تعداد دقیق رخدادهای ازدست‌رفته قابل اثبات نیست؛ ظرفیت buffer برابر ۲۰۰ است. این خرابی در helper آزمایش بود، نه مسیر اجرایی افزونه. سایر داده‌های سایت هدف این حذف نبودند.

نسخهٔ کامل قابل‌بازیابی در مسیرهای پشتیبان بررسی‌شدهٔ پروژه و WordPress پیدا نشد؛ binlog نیز فعال نبود. HTML قدیمیِ رندرشده backup کامل محسوب نمی‌شود و وارد لاگ نشده است. لاگ تاریخیِ حذف‌شده بازیابی‌شده اعلام نمی‌شود. برای بازیابی بیشتر، backup واقعیِ پیش از رخداد لازم است.

## علت

`restore()` پیش از تهیهٔ snapshot اجرا می‌شد. مقدار پیش‌فرض snapshot مفقود، آرایهٔ خالی بود؛ بنابراین شاخهٔ «گزینه قبلاً وجود نداشته» اشتباهاً اجرا و لاگ زنده حذف می‌شد.

## اصلاح

- snapshot مفقود اکنون `null` است و cleanup بدون هیچ تغییری برمی‌گردد.
- snapshot نامعتبر خطا می‌دهد و لاگ زنده دست‌نخورده می‌ماند.
- snapshot پیش از ایجاد draft ذخیره می‌شود.
- cleanup فقط draft علامت‌گذاری‌شده و رخدادهای متعلق به fixture را حذف می‌کند؛ رخدادهای جدیدِ غیرمتعلق به تست نیز حفظ می‌شوند.
- regression مستقل `activity_log_fixture_lifecycle_check.cjs` حالت no-op، restore تکراری، حفظ log قبلی و رخداد هم‌زمان، حذف draft متعلق به fixture و بازگرداندن snapshot خود تست را بررسی می‌کند.

نتیجهٔ regression: **۴ بررسی PASS، exit 0**. ماتریس مرورگر نیز چهار حالت انگلیسی/فارسی و خالی/پر را با cleanup موفق گذراند؛ [گزارش نهایی A2.10](ACTIVITY_LOG_A2_10_EXECUTION_REPORT_FA.md). اصلاح helper به معنای بازیابی دادهٔ تاریخی نیست.
