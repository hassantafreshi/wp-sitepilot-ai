## Defects found and fixed in this round

1. **Country → state link broken.** EFB keeps the canvas order (`amount`) as a number, gives an option its
   field's number and, after its own Save, stores the numbers as strings and compares them as such. The
   copilot wrote strings and numbered options too, so a country list (7) and its state list (249) no longer
   compared as neighbours and the state list never reloaded. Numbering now matches EFB's.
2. **Settings row counted as a field** once the form type was `login` (or `payment`): the sign-in fields went
   in above the step header. The settings row is now recognised by position.
3. **HTML block kept script code as text** (`wp_kses_post` removes the tag, not its content). Code-carrying
   elements are removed with their contents first.
4. **Partly refused batch kept the model's sentence** ("SMS is on") although SMS was refused. The reply is
   replaced when part of a batch is refused.
5. **A field setting on a field added in the same message was dropped** (confirmation SMS on a new mobile field).
6. **Open settings panel went stale** after any AI change; it is redrawn (and closed when its field is removed).

## Observed in Easy Form Builder itself (not changed here)

- EFB's Save stores `amount` as a string and its runtime compares the strings, so in EFB's own forms a
  country list numbered 9 with a state list numbered 10 would also lose the link ("10" > "9" is false).
- The settings panel shows a redirect address with one slash after the scheme (`https:/example.com`); the
  stored value and the redirect itself are right.
- On the demo's page cache the mobile field logs `window.intlTelInput is not a function` once.
- On the demo build the Stripe secret-key input is `type="password"`, which EFB's settings reader does not
  read; the current EFB source uses `type="text"` and is not affected.
